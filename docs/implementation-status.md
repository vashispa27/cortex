# Implementation status

Updated 16 October 2026. This document distinguishes implemented behavior from proposed requirements in [the specification](../goldfish-end-to-end-spec.md).

## Verified in this workspace

- Snapshot cleaner v3 is implemented in the macOS CLI. The AX helper emits bounded ancestor paths and visible bounds, and SQLite keeps the original `ax_nodes_json` with cleaned `body`, quality, coverage, and per-node removal reasons. A dry run over 61 stored snapshots showed the ChatGPT nutrition recommendation and every cited quantity retained while sidebar, browser controls, prompt box, and feedback controls were removed. The applied migration merged duplicate snapshots, marked navigation-only screens unsearchable, regenerated derived entries, and rebuilt Qdrant with message/paragraph chunks. Eight older captures had no saved AX nodes, so their originals remain in SQLite but are unavailable to the clean index. `ask "olive oil"` retrieved the cleaned ChatGPT source and full URL. This is a local-data verification; a fresh live capture with the new ancestor paths has not yet been inspected.

- The new `open-memory` macOS CLI builds and completed a live Accessibility check after the helper was granted permission. Safari exposed a local HTML chat page, its full `file:///private/tmp/open-memory-browser-check.html` URL, 20 ordered Accessibility nodes, and a displayed `10:42 AM` message time. `capture --print` stored the screen in SQLite as snapshot #2 and repeated polls updated its sighting count without another snapshot. A later capture of the same page stored all 20 ordered AX nodes in SQLite's `ax_nodes_json` column; 20 observations shared snapshot #3. Local Model2Vec indexed it into Qdrant Edge; `ask` retrieved its original text and URL while capture was running and after capture stopped. A Chrome Incognito window on the same page also exposed the text and full `file:///tmp/open-memory-browser-check.html` URL; capture stored it as snapshots #4 and #9 when toolbar metadata changed, with the same message evidence and `some_element_bounds_unavailable:2`. The latter snapshot has `browser_private` source type. The CLI keeps originals in its own SQLite database and offers capture/ask through a private Unix socket while capture runs. The prior desktop workflow remains distinct and still passes `--skip-browsers` to the shared helper before reading a browser tree.

- Rust capture policy defaults to no consent, rejects private or unknown browser context, excluded apps/domains/windows, protected UI subtrees, and inactive sessions. It bounds traversal and redacts covered secret formats before hashing and persistence.
- SQLite stores sanitized source versions separately from observations, with transactional FTS triggers. Search uses observation timestamps for date filters. Selective and whole-store deletion advance a memory epoch, remove dependent derived records, pause capture, and return a receipt. Ordinary SQLite deletion does not guarantee SSD or backup erasure.
- The loopback daemon uses a random per-install bearer token in a private state directory, checks Host/Origin, and exposes status, typed settings, search, exact sources, recent and deduplicated working memory, day digests, tracked foreground time, and deletion. Its macOS worker runs only after a persisted capture choice and Accessibility permission. It rechecks pause, exclusions, settings version, and deletion epoch before committing an observation. Synthetic ingestion remains an explicit offline CLI command.
- The MCP stdio bridge uses the official TypeScript SDK, requires the daemon's separate `mcp_enabled` setting, and exposes six read-only tools. Client registration preserves other strict-JSON entries and removes only an unchanged owned entry.
- The Tauri shell builds as a macOS app, embeds and starts the daemon, and proxies allowlisted routes without exposing the token to React. Capture settings now offer Start, Pause, Stop, permission request, and applied exclusions. A prior native smoke test connected it to an isolated synthetic daemon, loaded a recent source, and opened its exact stored text; live AX reading remains unverified. The browser sample includes onboarding, evidence browsing, a sandboxed writing tutorial, and reminders. The current chat view returns local search results for inspection; it does not claim a generated answer.
- The cloud gateway enforces signed OIDC access tokens outside development mode, explicit cloud consent, bounded schemas, idempotency keys, quota, source-ID validation, and format-aware credential rejection. The control service stores metadata rather than an archive. Development mode uses a deterministic mock provider.
- The public website has an original identity, responsive preview pages, and unavailable downloads until artifacts are configured. Release metadata tooling checks an external Ed25519 signature, local artifact hashes, and remote artifact bytes at an allowlisted HTTPS download origin before exporting URLs.

## Native feasibility and release gates

| Gate | Current result |
|---|---|
| macOS AX permission | Granted to the new CLI helper during this check. Safari, Chrome Incognito, and the Codex app were read through Accessibility. Other-app and long-running battery coverage remain unverified. |
| Windows UI Automation | Out of scope for this macOS implementation. An earlier probe remains in the repository. |
| Cross-app insertion | Guarded UTF-16 selection and stale-target logic pass synthetic tests; no supported real-app matrix is established. |
| Capture service | The macOS worker polls foreground Accessibility text through a bounded helper only after consent, permission, and exclusions. It skips browsers and known credential apps before AX reading. Live third-party capture, app compatibility, and resource use still need verification with user-granted permission. |
| Voice | An explicit, time-limited local microphone scratchpad and gateway route contract exist; no live speech provider or verified cross-app insertion is configured. |
| Memory quality | Lexical retrieval and deterministic day digests exist. Entity wiki, commitments, style learning, hierarchical summaries, and 200-case evaluation sets are not implemented. |
| Account and cloud | Gateway OIDC verification exists. Desktop PKCE sign-in, credential storage, and production provider configuration remain. |
| Proactivity | Preview reminders are local to the shell; no device scheduler with DST/catch-up guarantees or evidence-based nudges exists. |
| Distribution | Manifest verification and CI definitions exist. Signed/notarized installers, updater, rollout, performance/battery results, and production deployment remain. |

Do not enable personal capture, external AI client access, or cloud processing as a side effect of building or verifying the app. Each needs its own explicit user choice and OS permission where applicable. A macOS release requires native app validation and the quality/security gates in spec section 16.
